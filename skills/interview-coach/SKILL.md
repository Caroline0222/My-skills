# 面试陪练 (Interview Coach)

## Overview

把候选人提供的 JD + 简历 + 公司信息，**结构化为 6 章、可扫读、可被验证的面试弹药库**。覆盖 HR Screening → Hiring Manager → Case → Panel → 终面全流程，适用于**全行业**社招候选人。

**核心原则**：
- 信息不足先追问，**不虚构、不夸大、不写鸡汤**
- 所有论断必须能追溯到候选人提供的 JD 或简历原文
- 输出物**可被验证**：每个故事有数据，每个能力有证据

## When to Use

- 候选人拿到面试机会（猎头推荐、内推、主动投递）
- 提供目标岗位 JD + 个人简历
- 想在面试前理清"怎么讲自己的故事"

**不要用于**：实习 / 校招、薪资谈判、面试后复盘（用其他 skill）。

## 必备 vs 可选输入

| 字段 | 必备 | 缺失处理 |
|---|---|---|
| 目标岗位 JD（完整文本） | ✅ | 必须追问 |
| 个人简历（含最近 3 段 + 量化结果） | ✅ | 必须追问 |
| 公司名称 / 行业 | ✅ | 必须追问 |
| 行业 / 职能 | ✅ | 决定 E 章节按需启用 |
| 面试轮次 | 可选 | 没给时 E 章节全形式铺开 |
| 猎头 / HR 沟通记录 | 可选 | 大用——常暗示面试重点 |

## 工作流（6 章 A-F）

**严格按 A→B→C→D→E→F 顺序**，信息缺口在追问环节一次问清（最多 3 个问题）。

### A｜了解机会

公司一句话 + 岗位为什么存在 + 必知 3 件事。

**不追求百科全面，只追求与岗位有关。** 行业地位、完整竞品、所有产品线 → 降级为按需项。

详见 `references/company-research.md`。

### B｜我的定位

两段就够：**30 秒定位**（开场）+ **Why me**（被问匹配度时）。

- 不要从"我做过什么岗位"开始，而从"我擅长解决什么类型的问题"开始
- 每段必须有 1 个数字

详见 `references/candidate-positioning.md`。

### C｜证据 + 故事

**4 列证据矩阵**（精简版）：JD 要求 / 我的证据 / 等级 / 可能追问。

证据等级：
- 🟢 **直接证据**：有真实经历、具体动作、可解释结果
- 🟡 **可迁移证据**：领域不同但能力结构相似
- 🔴 **待补足项**：没有直接证明，需准备应对策略

必背 **6 类故事**（覆盖代表性成果 / 最难挑战 / 冲突 / 失败 / 主动改进 / 快速学习）。

详见 `references/evidence-and-stories.md`。

### D｜准备 + 深挖

3 类深挖准备：
- **简历深挖**：每段经历的防守卡（加入 / 离开 / 成果 / 高风险问题）
- **故事深挖**：每个核心故事做三级追问（事实 → 判断 → 复盘）
- **专业深挖**：按岗位准备 3-5 个深挖题答案

详见 `references/prep-and-deep-dive.md`。

### E｜适配 + 练习

按岗位**按需启用**面试形式：HR Screening / Hiring Manager / Behavioral / Situational / Professional / Case / Presentation / Portfolio / Take-home / Role Play / Panel / Final。

**Case 通用作答 8 步**（如启用 Case）：明确目标 → 澄清现状 → 提出假设 → 拆解问题 → 做优先级 → 给出方案 → 定义验证 → 总结结论。

最小练习包：30 秒定位 + 1 分钟自我介绍 + 2 个核心故事（1/2/5 分钟版）+ 1 个失败 / 冲突 / 离职原因 + 3 个反问。

详见 `references/interview-formats.md`。

### F｜最终执行

**面前 → 面中 → 面后**三阶段时间线：

- **面前 T-24h**：核对 JD / 公司动态 / 面试形式 / 时长 / 面试官公开主页
- **面前 T-12h**：过一遍 6 章弹药库，每个故事至少念 1 遍
- **面前 T-1h**：4 段定位 + 必知 3 件事默背；设备 / 网络 / 链接测一遍
- **面中**：先说结论再补充；分清个人 / 团队贡献；Case 先澄清；最后反问确认成功标准
- **面后 T+0**：趁热记 5 分钟（问过什么 / 答得不好的 / 面试官透露的信息）
- **面后 T+24h**（可选）：复盘 1 次（哪段最好复用 / 哪段最该改 / 下次调整）

详见 `references/execution-checklist.md`。

| C | 证据 + 故事 | 4 列证据矩阵 + 6 类故事标签 |

**形式**：单个 HTML 文件（6 章同页面，候选人可直接打开）+ Markdown 副本（备查）。

## 硬性约束

| 禁止 | 例外 |
|---|---|
| 不虚构简历里没有的项目 / 数据 | 必须用候选人原话 |
| 不夸大数据 | 写数字，不写"显著提升" |
| 不写通用鸡汤 | 删掉"勇于挑战、乐于奉献" |
| 不替候选人做 offer 决策 | 决策性问题留给候选人 |
| 不预设岗位类型 | 按 E 章节按需启动 |
| 不写"⭐⭐⭐"主观评分 | 用 🟢🟡🔴 证据等级 |

## 红线检查清单

- [ ] 每个论断都能追溯到候选人简历 / JD 中的某一行
- [ ] 至少 3 个量化数字
- [ ] 无空话套话（"赋能 / 抓手 / 闭环 / 沉淀 / 打造" 都不应出现）
- [ ] B 章节 2 段定位完整（30 秒 + Why me）
- [ ] C 章节至少 3 条 🟢 直接证据
- [ ] C 章节 6 类故事标签全列
- [ ] D 章节每段简历都有防守卡
- [ ] E 章节按岗位按需启用
- [ ] F 章节面前 → 面中 → 面后分阶段
