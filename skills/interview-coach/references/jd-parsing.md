# JD Parsing — 拆解 JD 的方法论

## 五层拆解

任何 JD 都可以拆成 5 层。逐层过一遍，C / D / E / F 模块的输入就齐了。

### 第 1 层：岗位身份
- 岗位名（产品经理 / 技术经理 / 高级运营 / 销售总监 …）
- 职级（P6 / P7 / 3-2 / T5 …）
- 汇报对象（推测：总监 / VP / CTO）
- 团队规模（JD 通常会写）

> 输出：1-2 行，**岗位在组织里的位置**。

### 第 2 层：核心目标（Why this role exists）

JD 第一段通常写"我们正在寻找一位 XXX，负责 …"。这是岗位存在的理由。

- **识别**：动词 + 业务名词 + 期望结果
- **示例**："负责 XX 业务的增长，通过产品迭代和运营策略，在 6 个月内将 DAU 提升 30%"
- 提炼成 1 句**目标陈述**——A 模块"岗位为什么存在"直接引用此句。

### 第 3 层：关键能力（Must-have）

任职要求里的硬条件。**最多 5 项，多了就是没重点**。

如何识别：
- "必须 / 至少 / 不少于 / 3 年以上" → Must-have
- "熟悉 / 了解 / 加分 / 优先" → Nice-to-have

每项能力 = 一个动词 + 一个名词

| 示例拆解 | 动词 | 名词 |
|---|---|---|
| 5 年以上大型分布式系统经验 | 维护 / 设计 | 分布式系统 |
| 优秀的跨部门协作能力 | 协调 | 多方利益 |
| 有从 0 到 1 搭建经验 | 搭建 | 0→1 业务 |

### 第 4 层：隐性偏好（潜台词）

JD 里那些"听着要求其实在筛选人"的词。

| 潜台词词 | 解读 | 面试时该强调什么 |
|---|---|---|
| 抗压能力强 / 能扛事 | 业务压力大、加班常态 | "过去 X 段高压经历 + 怎么扛下来" |
| 自驱 / 主动 | 团队没有精细管理 | "我习惯自己找事做的 1 个例子" |
| 沟通协调 / 推动跨部门 | 公司内部门墙明显 | "我推动跨部门落地的 1 个项目" |
| 业务 sense / 商业思维 | 不需要纯执行，要能往上思考 | "我对业务的 1 个非共识看法" |
| 拥抱变化 / 适应快节奏 | 公司业务 / 组织调整频繁 | "我经历过的 1 次业务转型" |
| 有创业心态 | 给的 title / 资源不一定到位 | "我接受过 title / 资源不到位并做出成果" |
| 0 到 1 / 早期阶段 | 没成熟体系，要从混乱里建秩序 | "我搭过的 1 个从 0 到 1 的体系" |
| 闭环 / 全链路 | 公司流程不完整 | "我打通过的 1 条链路" |

> **用得上**：把潜台词翻译成"候选人面试时该强调什么"，写到 E 模块"履历防守卡"和 D 模块"故事库"里。

### 第 5 层：暗线信号

从格式 / 语气里读出来：

- **JD 长度**：过短 = 招得急 = 可能是救火岗；过长 = 部门成熟、流程规范
- **薪资范围是否写**：写了 = 真实范围紧；没写 = 有谈判空间
- **"急聘 / 马上到岗"**：候选人可争取更早入职，但对方议价空间小
- **"团队 N 人"**：人数是组织阶段信号
- **JD 同一岗位多份**：可能有不同 leader 在抢人 = 内部博弈
- **岗位重复出现**：公司在批量扩张或大面积流失

## 颗粒度

拆解输出用于 E 模块履历防守卡时，**每层 2-4 行**，不要全展开。

## 检查

拆完后自检：
- [ ] 关键能力已按 Must / Nice 分级
- [ ] 至少识别 2 个潜台词词
- [ ] 能用一句话讲清"这个岗位要解决什么问题"（用于 A 模块"岗位为什么存在"）

## 输出到 C 模块的衔接

JD 五层拆解完成后，把第 3 层"关键能力 Must-have"直接喂给 `evidence-matrix.md`：

```
JD 要求 | 真正考察的能力 | 面试官可能怎么验证 | 我的证据 | 证据等级 | 可能追问
```

JD 关键能力 → 第 1 列；每条都要拆到第 2-6 列才算 C 模块完成。
