# 大模型选型七步闭环 (LLM Model Selection)

## Overview

把客户的业务需求与合规边界，转成**可交付、可被追问、可被验证**的模型选型方案。适用于写标书技术方案、方案沟通材料、客户答疑、售前被追问。

**核心原则**：
- **排除法优先**：先问"哪些是不能选的"，再问"哪个最好"。四闸触发即出局，硬约束不参与比选
- **不制造质量差异**：分数接近就写"无显著差异"，不许把 0.5% 说成优势
- **每个数字能指到来源**：型号、参数量、显存、许可、单价，只允许来自客户原文或官方文档

## When to Use

- 客户给了业务场景 + 合规要求，需要给出模型选型与理由
- 投标技术方案需要写"选型依据"章节
- 客户问"为什么不选 XX""为什么不用开源""自建还是调 API"
- 需要把"我们认为该选什么"变成客户能验收的结论

**不要用于**：模型微调 / 训练方案设计（用其他 skill）、GPU 采购选型、AI 平台产品选型、纯 API 接入开发。

## 什么时候根本不是「选型」

**这一节比后面六步都重要。** 很多标书里的"选型"其实是排除法的包装，硬跑七步反而暴露判断力不足。

| 情形 | 实质| 正确做法 |
|---|---|---|
| 四闸（许可/显存/驻留/国别）已排除到只剩 1 个 | **排除法** | 直接写"经四闸收敛仅 X 可行"，不要硬做多模型比选 |
| 客户已指定品牌（如"必须用通义"） | **排除法** | 写"在指定品牌内的档位建议"，型号可写"由研发按客户算力定" |
| 部署形态已被招标条件锁死（内网物理隔离） | **排除法** | 写"满足条件的部署形态只有本地部署"，不要假装在比选 |
| 硬件已定（客户自有工作站/指定卡型） | **受约束比选** | 从"显存装得下"的档位里比，显存闸直接反推参数量上限 |
| 效果基线未定义且客户拒答| **不成立** | 明确写"效果基线缺失，选型无法收敛"，附需客户确认清单 |

**方案层 vs 研发层的决策边界**（越界就是编）：

| 层 | 定什么 | 不定什么 |
|---|---|---|
| **方案层（售前）** | 许可可行性、部署形态、架构方向（稠密/MoE/多模态）、性能档位、兜底方案 | 具体型号、量化精度、推理引擎与并行策略、微调方案 |
| **研发层** | 具体 checkpoint、量化位宽、vLLM/SGLang 配置、并行拓扑、微调与蒸馏 | — |

客户原文只写品牌时，方案层就只写品牌 + 部署形态，型号标「由研发按客户算力定」。**诚实划界比编一个型号可信得多。**

## 必备 vs 可选输入

| 字段 | 必备 | 缺失处理 |
|---|---|---|
| 业务场景与要解决的问题 | ✅ | 必须追问 |
| 数据分级与驻留法域 | ✅ | 必须追问（一票否决前提） |
| 客户已有硬件 / 算力约束 | ✅ | 必须追问 |
| 峰值并发 + 年请求量 | ✅ | 必须追问 |
| 效果基线（准确率/通过率目标） | ✅ | 拒答则写"选型无法收敛" |
| 输出语言（是否需生成粤语/繁中） | 可选 | 缺失按"需要多语言"保守处理 |
| 运维能力（有无 MLOps 团队） | 可选 | 缺失则优先推荐托管/API |
| 许可类别要求 | 可选 | 缺失按 Apache 2.0 及以上 |
| 锁版要求 | 可选 | 缺失按"可换版"处理 |
| p95 时延目标 | 可选 | 缺失则 PoC 实测代替 |

## 工作流（7 步）

**严格按 1→7 顺序。** 第 1 步没跑完不要进第 4 步——在已被排除的候选里比规格是白做。信息缺口在第 2 步一次问清（最多 3 个问题）。

### 1｜一票否决四闸

许可 / 硬件显存 / 数据驻留 / 来源国别，**四条任一触发即排除**，不做权衡。许可读**具体 checkpoint 的 LICENSE**；量化后 `权重 + KV cache ≤ 可用显存 × 0.85`；推理、存储、备份**三个位置**都要在法域内。

详见 `references/constraints-and-veto.md`。

### 2｜问客户 10 项

效果基线 / p95时延 / 数据分级 / 驻留法域 / 输出语言 / 许可类别 / 运维能力 / 年请求量 / 峰值并发 / 锁版要求。**这 10 项任何模型清单都替代不了。** 缺项用行业默认值补，但必须标「假设，需客户确认」。

详见 `references/constraints-and-veto.md`。

### 3｜定架构

交互式低并发 or 批量高吞吐 → 稠密 or MoE；要不要视觉/OCR；真实文档长度 P95。**batch=1 稠密赢、batch>32 MoE 赢；MoE 省算力不省显存**（总参数决定显存）。标称上下文 ≠ 可用上下文，按真实语料 P95 算。

详见 `references/architecture-and-specs.md`。

### 4｜比规格

先列候选池（**至少 2 个模型家族**），再横向比8 个维度：总参 / 激活参 / 架构 / 原生上下文 / 扩展方式 / 4-bit 权重显存 / KV cache / 许可。**只在通过第 1、3 步的候选里比**，型号必须回原始文件逐字核对。

详见 `references/architecture-and-specs.md`。

### 5｜跑 PoC

≥100 个真实业务用例（变化大则 500+），预留 20% 盲测集，三维度打分：质量 / 单任务成本 / 延迟。**同一套 prompt 跑所有候选**，业务方盲评仲裁，权重先定后跑。

详见 `references/poc-and-cost.md`。

### 6｜定结论 + 算成本

统计上接近时，按 成本 / 时延 / 治理 / 集成复杂度 选，**不制造质量差异**。成本必须按**「每个成功任务的成本」**算，不是每百万 token 单价：

```
C_api  = (T_in × P_in + T_out × P_out) × R / S
C_self = (年GPU 小时 × 单卡小时成本 + 年运维分摊) / 年成功任务数
```

**算钱用年请求量法，验容量用峰值并发法**——两个结论别混。

详见 `references/poc-and-cost.md`、`references/decision-and-governance.md`。

### 7｜上线治理

回归测试集 + 第二个已批准模型 + 测过 failover。重跑时机：供应商大版本 / 检索数据变更 / 用户行为变化 / 硬件换代。

详见 `references/decision-and-governance.md`。

## 输出物

主交付 = **单个 HTML 选型报告 + Markdown 副本**。

| 块 | 章节名 | 主要交付 |
|---|---|---|
| 0 | 报告头 | 项目代号（脱敏）/ 版本 / 检索日期 / 密级 |
| 1 | 客户约束表 | 10 项约束 + 一票否决判定矩阵 |
| 2 | 候选收敛过程 | 每轮排除谁、依据哪条闸|
| 3 | 架构方向 | 稠密/MoE 判断 + batch 区间依据 |
| 4 | 候选矩阵 | 2–3 个入围的横向规格对比 |
| 5 | PoC 分数矩阵 | 三维度 + 显著性 + 盲评一致性 |
| 6 | 成本测算 | 每成功任务成本 + 三年 TCO 三档 + 盈亏平衡点 |
| 7 | 结论与风险 | 主推 + 备选 + 切换触发器 + 兜底 + 给客户的一句话 |
| 附A | 需客户确认清单 | 待确认项 + 影响哪个结论 + 确认后重跑哪步 |
| 附 B | 版本与重跑时机 | 模型版本检索日期 + 触发条件 |

详见 `references/selection-report-template.md`（表结构）、`assets/selection-report-template.html`（样式）。

## 交付前自检3 问

**这三条比十页方案更能证明判断力。** 每份报告交付前逐条过：

1. **如果客户明天改掉某条约束（C3 数据不出境、C6 需生成粤语），这个结论会不会翻？** 不会翻 → 那条约束是装饰品，不是硬约束，删掉或标为"参考项"
2. **每个型号数字能指到官方 config.json / 模型卡，或客户方案原文的某一行吗？** 指不到 → 标「需核实」，不写进结论
3. **主推和备选的差别，是成本差还是硬约束差？** 如果只是成本差，要说清差多少个百分点；如果硬约束差，说清是哪个闸

## 硬性约束

**完整 12 条见下方红线检查清单。** 冲突时以红线清单为准。最容易踩的四条：

| 禁止 | 正确做法 |
|---|---|
| 只给一个模型 | 必须主推 + 备选 + 切换触发器；无候选通过时写"无可用候选 + 放宽哪条" |
| 编价格 | 单价留占位标「待填 + 来源」，只给公式与口径 |
| 越界替研发定型号 | 方案层只定到档位，型号标「由研发按客户算力定」 |
| 把排除法包装成比选法 | 见「什么时候根本不是选型」 |

## 红线检查清单

- [ ] 四闸都跑过了，每条排除都有依据编号
- [ ] 10 项约束表填满，缺失项标了「假设，需客户确认」
- [ ] 已判定本次是排除法还是比选法，并在报告里说明
- [ ] 型号是逐字抄的，能指到 config.json / 模型卡 / 客户原文
- [ ] 每个候选的许可按该 checkpoint 单独查过，未按家族推断
- [ ] 每个结论标了约束编号（如 `[C3][C7]`），能反查到约束表
- [ ] 主推 + 备选 + 切换触发器齐全
- [ ] 成本给的是每成功任务成本，含放大系数 R 与成功率 S
- [ ] 所有单价字段标了来源，没有编造数字
- [ ] 统计接近处写的是「无显著差异」，没有拔高
- [ ] 结论不是「参数越大越好」，落在效果/成本/时延/治理之一
- [ ] 已划清方案层与研发层的决策边界
- [ ] PoC 用同一套 prompt，权重先定后跑，盲测集 ≥ 20%
- [ ] 交付前自检 3 问都过了
- [ ] 全文无赋能 / 抓手 / 闭环 / 打造 / 深度融合 等 AI 味词
- [ ] 全文无客户实名、无报价金额
- [ ] 模型版本标了检索日期，距今不超过 6 个月
