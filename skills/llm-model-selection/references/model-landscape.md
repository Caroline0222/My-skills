## 快照口径

**这份文件不是型号库，是"别讲停在旧版本"的对照表。**

用法：方案里引用某个型号时，**必须同步说明同档位现在有什么**。目的不是显得更新，是让客户看到你还在跟生态。

| 用途 | 不用它做什么 |
|---|---|
| 说明同档位现状 | ✗ 不作为"当前最强模型"的排行依据 |
| 提示换版可能性 | ✗ 不作为型号逐字核对的来源（来源见 §来源） |
| 判断是否值得换版 | ✗ 不替代 PoC |

## 开源权重同档位现状

| 版本 | 日期 | 架构 | 上下文 | 显存要点 | 许可 |
|---|---|---|---|---|---|
| Qwen3-32B | 2025-04 | 稠密 | 原生 32K，YaRN 至 128K | AWQ INT4 约 19.3GB，单张 24GB 卡可跑 | Apache 2.0 |
| Qwen3-30B-A3B-Instruct-2507 | 2025 | MoE，30B 总 / 3B 激活 | 128K | Q4 约 18–19GB，KV cache 约 3GB，**解码快 2–3 倍** | 见模型卡 |
| Qwen3.6-35B-A3B | 2026-04 | MoE，35B 总 / 3B 激活，256 专家 | 256K → 1.01M | 需实测 | Apache 2.0 |
| Qwen3.8-27B | 2026-08 | 稠密 27B | — | 4-bit 装 24GB 单卡 | Apache 2.0 |

### Qwen3-32B 关键规格（ModelScope 官方 config.json）

| 项 | 值 |
|---|---|
| 架构 | 32.76B 稠密 decoder-only · 64 层 · hidden 5120 · FFN 25600 |
| 注意力 | GQA，Q64 头 / **KV 8 头**（KV cache 压到 1/8） |
| 词表 | 151,936 |
| 上下文 | **原生 32K**，YaRN 扩展至 128K |
| 显存 | BF16 65.5 GB ｜ FP8 34.3 GB ｜ **AWQ INT4 19.3 GB** |
| 许可 | Apache 2.0，无收入门槛 |
| 推理模式 | 同一份权重可切思考 / 非思考，AIME 2025 上 **72.9 vs 20.2** |

> ⚠️ 两个常见错误：网传 hidden 4096 / FFN 11008 是上一代 32B 的数据，不是 Qwen3-32B；另外 `max_position_embeddings` 配置值≠ 上下文窗口。
>
> **KV cache 陷阱（要写进方案）**：32K 上下文 BF16 下约 8.6 GB/请求，10 并发即约 86 GB —— **4-bit 模型在高并发长上下文下，KV cache 可能比权重还大**。详见 `constraints-and-veto.md` 闸 2。

### 已知的单项退步（主动说更可信）

| 型号 | 指标 | 变化 |
|---|---|---|
| Qwen3-30B-A3B-Instruct-2507 | MultiIF（多语言指令跟随） | 从 70.8 **退到 67.9**（唯一退步项） |
| 同型号 | Arena-Hard v2 | **69.0**，超过 GPT-4o 的 61.9 |

> **两个方向都要说。** 只报 Arena 分数不提 MultiIF 退步，客户测出多语言变差时会认为你在藏。主动说退步项，整份报告的可信度会上升。

## 许可必须按 checkpoint 读

**这是本文件最重要的一条。**

**不能按家族名推断许可。** 同一家族不同 checkpoint 可能完全不同：

| 情况 | 判定 |
|---|---|
| Qwen3-32B、Qwen3.6-35B-A3B、Qwen3.8-27B | Apache 2.0，无收入门槛 |
| **Qwen3.8-Max（2.4T 总参 / 95B 激活）** | 开源权重**已改自定义许可**，集团年收入 **> US$50M** 的 MaaS 业务**需另签商业协议** |

> **"某某都是 Apache 2.0"是错的。** 旗舰checkpoint 可能已经改许可带门槛。判断规则永远是：**去读你要用的那个 checkpoint 的 LICENSE 文件。**
>
> 这条在评审时会被客户合规或法务直接否掉，代价极高。

## 「别讲停在 2025」表述纪律

**场景**：方案或答疑里提到了某个较早的型号。

**必须补一句**：

| 做法 | 示例 |
|---|---|
| ✅ 同步现状 | "本方案基于 [型号]（2025-04 发布）。同档位目前已有 [新版本]（日期、架构差异），如需评估换版可另做 PoC。" |
| ❌ 只讲旧型号 | "本方案采用 [型号]。" |

> **为什么重要**：模型迭代很快。方案里只写一个旧型号不提同档位现状，会显得信息停在旧版本——**这在客户侧比"型号选错"更伤信任**。

**正确姿态**：不是说"旧型号不行"，而是"我们选这个是因为匹配这些约束，同时我们知道同档位现状，如果约束变了可以评估换版"。

## 不确定项清单

**以下条目无可靠公开来源，不得当事实写进方案。**

| 项 | 情况 | 怎么讲 |
|---|---|---|
| 特定监管文件的全文 | 业内广泛流传，官网无公开全文 | 被追问来源就承认是行业通说，不要硬引条号 |
| 各家市场份额百分比 | 来源均为咨询或自媒体，无官方统计 | 不引用；客户问就说无官方统计 |
| 母公司/集团上市状态 | 需查交易所公告确认当前状态 | 讲"某地上市"前先查港交所或交易所公告 |
| 项目承建商归属 | 须以公告为准，不推测 | 只讲公开可查的归属关系 |
| 未见正式公告的事项 | 说"截至 [日期] 未见公告" | 不用"正在筹备"这类推测表述 |

> **这五条不是本次特有的**，是售前通用纪律。列在这里是因为模型与厂商信息迭代快，最容易踩"旧信息当新消息"。

## 来源口径

**型号与规格的唯一合法来源**：

| 类型 | 去哪查 |
|---|---|
| 架构参数（层数/hidden/FFN/词表/上下文配置） | 官方 `config.json`（ModelScope / HuggingFace） |
| 基准分数、已知能力与限制 | 官方模型卡 + 官方博客 |
| 许可条款 | 该 checkpoint 的 LICENSE 文件 |
| 商业模型规格 | 厂商官方文档（不是二手文章） |
| 价格 | 厂商定价页，标检索日期 |

> **禁止**：二手技术博客的规格表、自媒体榜单截图、凭记忆写的参数。**每个数字要能指到上面某一类。**
