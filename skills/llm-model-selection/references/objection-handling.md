# 客户异议应答 + 诚信边界

投标与客户沟通现场用。**应答结构固定，不要临场发挥。**

---

## 通用应答结构

```
先承认 → 给判断依据 → 给验证方式 → 给兜底
```

| 步| 做什么 | 例子 |
|---|---|---|
| **先承认** | 承认对方的观察是真的，不辩驳 | "这个差距在实际测试里确实存在" |
| **给判断依据** | 说清差异来自哪、影响哪类任务 | "差距集中在长文本推理，短问答上不明显" |
| **给验证方式** | 用 PoC 或数据让客户自己确认 | "建议用贵司 100 条真实工单跑一次" |
| **给兜底** | 不达标怎么办 | "若通过率低于 X%，切到备选 [Y]" |

**不要跳第1 步。** 一上来就反驳，客户会觉得你在护方案，不是在解问题。

**第 4 步最容易被忘。** 没有兜底的应答听起来像在赌气。

## 异议 1｜开源效果差距

**客户原话（脱敏）**：
> "实际测试中开源模型（如千问 3-vl）效果与闭源模型（豆包、火山）差距较大。模型更新换代快，如何解决效果差距及后续升级的兼容性、测试成本问题？"

这句话里其实是**三个问题**，分开答：

### 1a 差距是否存在

**承认，并具体化**：

> "差距确实存在，但要看落在哪类任务。短文本问答、分类、抽取这类**有明确判定标准**的任务，开源模型与闭源差距不大。差距主要在**长文本推理、复杂多步逻辑、需跨文档综合**的任务上。"

**关键动作**：把"差距大"拆成"哪类任务差距大"。这比争论有无差距有效得多。

### 1b 差距有多大

**给验证方式，不要嘴说**：

> "建议用贵司真实语料跑一次：取 100–200 条真实工单，覆盖 [A/B/C 三类任务]，同一套 prompt 各跑一次，盲评打分。这样出来的是贵司场景的数字，不是公开榜单的数字。"

> **公开榜单不能替代 PoC。** 榜单用的语料、prompt、评分方式都跟客户场景不同。客户认可的是自己数据的数字。

### 1c 怎么选

**给决策框架，不给推销**：

| 任务类型 | 建议 |
|---|---|
| 有明确判定标准（分类/抽取） | 开源模型够用，省成本 |
| 复杂推理 / 长文档 | 看客户对质量的容忍度与并发要求 |
| 合规敏感、数据不出境 | 开源本地部署是**硬约束**，不是选择题 |

**最后一句最重要**：当数据不能出境是硬约束时，"哪个更好"根本不是问题。**此时应该把话题从"效果差距"转到"合规闸口"**——这是真正的决策依据。

### 1d 升级兼容性

**分层回答**：

| 层 | 做法 |
|---|---|
| 架构层 | 模型调用抽象成统一接口，换版不改业务代码 |
| 检索层 | 向量库与索引结构与模型解耦，换模型重跑索引即可 |
| 测试层 | 固定回归测试集（50–100 条），每次换版必跑，看指标变化 |
| 版本层 | 记录当前 checkpoint 全名与许可，换版前先过闸1 许可 |

> **回答这一问的核心是"换版要做什么"。** 客户真正担心的是"每次升级都要重做一遍"。答案应该是：抽象层已做、索引重跑是自动的、回归集能自动出报告——**升级成本从"项目"降级成"操作"**。

## 异议 2｜迭代快，测试成本高

**客户担心**：模型每几个月换一次，每次都要重测，运维负担重。

| 顾虑 | 回应 |
|---|---|
| 每次升级都要重跑 PoC | **回归测试集 50–100 条即可**，不是重跑 300 条 PoC。回归集测"有没有变差"，PoC 测"够不够好"，目的不同 |
| 谁来判断变好变坏 | 建自动评分：规则能判的（是否含关键要素、格式是否合规）全自动；需人判的只抽 20 条 |
| 版本怎么锁 | 记录 checkpoint 全名 + 许可文件版本。生产环境锁版，PoC 环境跟新版 |
| 跟不上版本怎么办 | 不必跟上。**定期看同档位是否有明显更优模型才动**，其余不动 |

> **最后一条是关键。** 客户怕的是"必须追最新"，但正确的策略是"**不追**"。锁版 + 定期复核，比每次都升级稳得多。
>
> 有个真实场景：客户已购硬件+ 模型，供应商后续发布更强版本，**正确答案是不换**——换版要重跑索引、重测、重走变更流程，收益未必抵得上成本。

## 异议 3｜自建还是调 API

**不站队，给盈亏平衡点。**

| 已有条件 | 倾向 |
|---|---|
| 已有硬件 | **自建边际成本低**，Q* 显著下降 |
| 无硬件、量小 | **API 更省**，先跑起来 |
| 无硬件、量大 | 看 Q* 与年请求量的关系 |
| 合规要求数据不出境 | **自建或国内云**，API 出海不可选 |

**应答模板**：
> "按贵司年请求量 [N] 测算，盈亏平衡点在 [Q*] 次/年。贵司当前量 [低于/高于] 该点，所以 [自建/API] 更省。这个数字会随请求量变化，三档 TCO 已列出（块 6b）。"

> **不要说"我们推荐自建"。** 给数字让客户判断，结论的牢固度取决于客户自己的信任度，而不是我们的语气。

**必补一句**：
> "若贵司三年内请求量增长快，建议 [混合方案]：大促/峰值走API，日常自建，切换点写在方案里。"

## 异议 4｜国产 / 开源能不能上生产

**先分清两个不同的问题**：

| 问题 | 判什么 |
|---|---|
| **能不能上生产** | 技术成熟度、运维能力、许可、升级路径 |
| **能不能上信创项目** | 客户国策、管制清单、验收标准 |

**很多争论是因为把两者混为一谈。** 一个模型完全可以满足前者但不满足后者。

**应答结构**：

1. 先确认客户是否有信创/国产化硬要求（**问，不要猜**）
2. 有要求 → 从信创清单里的模型开始比，不合规的不进候选池
3. 无要求 → 回到四闸 + PoC 正常流程
4. 有疑问 → 「需客户确认」，写进附A，让客户确认口径

> **不要因为客户说"要国产"就跳过闸1、闸2。** 信创清单里的模型也要看许可和显存能不能跑得起来。

## 异议 5｜数据不出境与开源权重

**常见误解**：客户以为"用开源模型部署在自己机房 = 数据安全"。

| 要说清的点 | 说明 |
|---|---|
| 权重来源也是数据路径 | 权重下载、镜像拉取、遥测上报都可能出境，需确认默认关闭 |
| 推理框架的外部依赖 | 某些推理框架默认上报统计信息，需核对 |
| 微调数据更敏感 | 微调数据往往包含更多内部信息，且权重文件要严格管控 |
| 备份与日志 | 推理日志、向量库快照是否也受驻留约束 |

> **主动提这些，客户会觉得你想得比他们细。** 被客户安全团队问出来就变成"你们没考虑周全"。

**应答模板**：
> "部署在贵司机房，推理与存储均在境内。但有三个位置需要额外确认：权重下载来源、推理框架的遥测上报、备份快照位置。方案里已列明这三项的确认清单（块 1b）。"

## 诚信边界表

**这是本skill 最重要的纪律。** 每次要写数字或下结论前对一遍。

| 情形 | 允许 | 禁止 |
|---|---|---|
| 型号 / 参数量 | 逐字抄客户原文或官方 config.json | 推断型号、凭记忆写参数量 |
| 价格 | 留占位标「待填 + 来源」 | 凭印象填、编造单价 |
| 效果数据 | 只写PoC 实测，且写明用例集规模与抽样方式 | 引用无法核实来源的宣传数字 |
| 许可 | 读具体 checkpoint 的 LICENSE | 按家族名推断 |
| 无公开来源的信息 | 写「行业通说」或「需客户确认」 | 写"业内一般""通常来说" |
| 客户拒答的约束 | 用行业默认值 + 标「假设，需客户确认」 | 当成客户要求写进承诺 |
| 方案层 vs 研发层 | 划清边界，型号标「由研发按算力定」 | 替研发定型号 |
| 分数接近 | 写「无显著差异」 | 把 0.5% 说成优势 |
| 退步项 | 主动写 | 只报优点 |
| 客户实名 / 报价 | 用脱敏行业代号 | 出现客户名、合同金额 |

### 通用标注三档

| 标注 | 什么时候用 |
|---|---|
| `已确认` | 客户文档或会议明确 |
| `需客户确认` | 影响结论但客户未给，列入附 A |
| `假设（默认值）` | 用了行业默认值，注明依据 |

> **三个标注只用这三个，不要自造。** 客户看报告时会默认这三个标注意味着不同可信度。

### 拿不准时的三个选项

| 选项 | 什么时候选 |
|---|---|
| 标「需客户确认」 | 影响结论、但可以并行推进 |
| 用保守默认值 + 标注 | 不影响架构方向、只是阈值 |
| **写"选型无法收敛"** | 影响结论且客户拒答（如效果基线缺失） |

> **第三个选项是真实选项。** 客户没给效果基线就硬选一个模型，是把假设包装成专业。明确写"选型无法收敛，请提供 C1"，比选一个然后被推翻好。

## 检查

交付前逐项过：

- [ ] 每条异议的应答都走了四步（承认 / 依据 / 验证 / 兜底）
- [ ] 客户提复合并问题时已拆开分别答（见异议 1）
- [ ] 效果主张都给了 PoC 验证方式，没有只报公开榜单
- [ ] 自建 vs API 给了 Q*，没有直接站队
- [ ] 升级成本的回答落到了"换版要做什么"
- [ ] 信创问题先问了客户是否有硬要求，没猜
- [ ] 数据安全的三个额外确认位置都提了
- [ ] 所有数字符合诚信边界表
- [ ] 标注只有 `已确认` / `需客户确认` / `假设（默认值）` 三种
- [ ] 无「行业一般」「通常来说」「应该是」这类无源表述
- [ ] 全文无客户实名、无报价金额
